# Tomori Live2D Viewer

一个跑在浏览器里的 Live2D 模型查看器兼动画编辑器，主要用来摆弄《BanG Dream! It's MyGO!!!!!》的高松灯和千早爱音模型：切模型、点动作表情、拖参数滑条、在时间轴上打关键帧、挂事件、配一段音乐，最后录成视频导出来。

纯前端项目，不需要后端。Live2D 运行时来自 npm 上的 `l2d` 包，已经随项目一起打包，断网也能正常跑。

## v2.0.0

版本功能与 v2.1 界面优化计划见 [发布记录](docs/RELEASES.md)。

时间统一显示为“分:秒:帧”的整数时间码，例如 30 FPS 下 `00:05:08` 表示 5 秒 8 帧，不显示小数秒。时间输入框可用上下键微调一帧，Enter 或离开输入框确认；内部仍按帧定位。

v2 发布保存在 `v2` 分支与 `v2.0.0` 标签；`v2.1` 用于下一版界面优化，默认打开场景编辑器。已验收的 v1 在远端 `v1` 分支和 `v1.0.0` 标签中，也可从页面右上角打开 v1 编辑器。

- 左侧模型素材点击添加到场景，同一模型可添加多次；每个片段独立控制。
- 模型片段有开始时间、显示时长、轨道和源时间偏移。不同轨道重叠时同屏，同一轨道前后排列时切换模型。
- 拖动时间线片段移动，拖动左右边缘裁剪；支持复制、删除和在播放头切割。切割保留源时间与内部动画。
- 上方轨道为上层，可拖动左侧图层卡片上下排序，或右键“向上一层 / 向下一层”；新建和复制模型默认插入顶层，排序支持撤销重做。
- 图层默认使用模型名称，可双击名称或通过右键菜单重命名。左侧锁与眼睛按钮可锁定、隐藏整层；锁定禁止画布拖动、片段和关键帧编辑及删除，但保持播放和导出；隐藏不参与画布及视频导出。状态随工程保存，支持撤销重做。
- 模型片段支持 Ctrl / Shift 多选、轨道空白处框选与整组拖动吸附；关键帧区域仍框选关键帧。Ctrl+C / Ctrl+V 复制粘贴整组模型到播放头，新副本插入顶层，保留时间间隔、关键帧、动作表情和源偏移；Delete 批量删除，锁定图层跳过选择，整组操作一步撤销重做。
- 时间轴右键菜单按轨道、模型片段、关键帧、动作和表情分组，显示所选数量、快捷键及禁用状态；模型多选可在播放头批量切割，关键帧可按片段、轨道或参数全选和清空。动作编辑开始时间、时长和源入点，表情只编辑切换时间。长菜单自动定位并滚动，离散菜单操作各占一步撤销。
- 点击画布或片段选中模型，在右侧编辑位置、缩放、旋转、透明度、原生参数、动作与表情。
- 画布随可用空间自适应放大；顶部「素材库」「片段属性」可收起侧栏，「放大画布」收起侧栏与时间线，「返回编辑」恢复布局。预览放大不改变录制分辨率。
- 统一播放头驱动片段显示和参数/变换插值；时间线展开选中片段的动作、表情和已编辑参数轨。关键帧支持多选、框选、拖动、复制粘贴和 Delete 删除，右键编辑。动作显示名称、进度及剩余时间；表情显示切换帧，从这一帧保持到下一表情帧，最后保持到模型离场，无时长和倒计时。两者支持选中、拖动、右键编辑、复制粘贴和 Delete 删除；动作左右边缘可裁剪源入点及出点，所有剪辑操作支持撤销重做。
- 导出完整场景工程 JSON；自动保存使用独立 v2 存储键。首次打开会复制已有 v1 工程，保留原始数据。旧 JSON 可导入迁移。
- 「录制场景」导出整张 960×540 合成画布，包含所有当前可见模型及背景；选择框不会进入视频。

时间线支持 1×–16× 缩放、横向滚动和“适合全长”。移动或裁剪片段时默认吸附到播放头、其他片段边界及工程首尾；黄色线提示吸附，按住 Alt 临时关闭。Ctrl / ⌘ + 滚轮在时间线内缩放。

每个模型片段直接显示关键帧菱形：黄色为画面变换，蓝色为身体参数；同一时间的同类参数合并显示，悬停可查看参数和值。选中后用关键帧栏选择参数、查看当前值及相邻帧、前后导航、增删和编辑数值。“展开关键帧”将所选参数及已有动画参数显示在模型轨道下方，支持拖动调整关键帧时间、右键编辑或 Delete 删除，编辑可撤销。关键帧不会再只藏在所有模型轨道的底部。

关键帧支持矩形框选及 Shift / Ctrl / ⌘ 追加多选，Delete 批量删除并可一次撤销。右键关键帧打开编辑菜单（不会立即删除），可编辑数值、时间及缓动；多选可批量设置缓动。右键模型轨道、片段或参数轨提供全选及删除该范围全部关键帧，包含裁剪隐藏的帧。关闭“框选”后，轨道空白处恢复拖动播放头。

本阶段已完成场景与多轨编辑基础、撤销重做、吸附和时间线缩放。动作事件按播放头触发，SDK 实时动作还不支持任意时间精确采样；动作精确跳帧、音频多轨尚待实现。详细约定见 [v2 开发计划](docs/V2_PLAN.md)。

## 快速开始

```bash
npm install
npm run dev        # 打开 http://127.0.0.1:5173
```

Windows 上也可以直接双击 `start.bat`，它会启动服务并自动打开浏览器。

其他命令：

```bash
npm run build      # 产出 dist/

```

## v1 功能参考

**模型浏览**：左侧列表按角色分组，点击即切换。模型是构建时扫描目录自动生成的，往 `public/models` 里放新模型不需要改代码。

**参数控制**：加载模型后读取它真实拥有的参数 ID、范围和默认值，支持老模型和 `adv` 新模型。底部默认显示常用参数，保留嘴部、眼睛、眉毛、表情、身体、头发等中文分组及常用中文标签；勾选「全部参数」可查看手臂、手指和其他高级参数，也能按中文名称或原始 ID 搜索。参数原名可悬停查看，滑条与数字输入框联动。每个参数右边有个 ◆，点击就在当前帧打一个关键帧，再点一次取消。

只有手动编辑或关键帧控制的参数会被固定，其他参数继续由动作、表情和物理效果驱动。每个参数旁的「重置」恢复它在当前模型中的默认值（不一定是 0），并删除该参数在当前帧的关键帧，不改变其他参数或其他帧；播放时禁用。「全部复位」恢复当前模型的默认值并释放手控。切换模型会停止播放、清理上个模型的手控覆盖；关键帧仍保留。

旧工程中的 `PARAM_EYE_L_OPEN` 等 ID 会按当前模型真实参数自动转换成 `ParamEyeLOpen` 等对应 ID，范围以当前模型为准。已经存在的真实 ID 关键帧优先，无法对应的轨道仍保留，切回原模型后可以继续使用。工程导出记录真实参数 ID。

**动作与表情**：右侧面板列出模型自带的所有动作组和表情，带颜色分类和使用时长提示。

新模型（`adv_` 系列）的动作只带动身体，表情是独立的 `exp_*.exp3` 资源——游戏里两者同时播放。应用会在**动作本身不带表情**时自动套用同名表情（`mtn_angry01_C` → `exp_angry01`），老模型的动作已经把表情写在参数里，不会被覆盖。

**时间轴**：可设时长和 FPS，用帧或秒定位，支持上一帧/下一帧/上一关键帧/下一关键帧。关键帧之间自动插值，每个关键帧可以循环切换线性、缓入、缓出、缓入缓出四种缓动，时间轴上用不同形状区分。

**事件轨**：点击事件轨选一帧，就能挂一个"到这一帧播放某动作"或"切换到某表情"的事件。

动作事件会占用一段区间（动作多长就占多长），区间内不能再放别的动作——两个动作叠着放，后一个会被前一个压住播不出来，所以这是刻意的限制。为了让这件事可操作：

- 模型加载后会直接读取动作文件算出每个动作的真实时长，不必先播一遍，下拉里每项都标着时长
- 选择器会告诉你当前帧是否空闲、从这里起还能放下多长的动作；放不下时会说明被谁占了、占到第几帧
- 放不下时提供"插入到第 N 帧"一键挪到最近空位，重新算好剩余空间
- 事件条可以直接左右拖动换位置，松手时会自动吸附到不与其它动作重叠的位置；点击（不拖动）则删除
- 旧工程里用估算时长放下的重叠事件会用红色斜纹标出来，提示需要调整

表情事件不占区间，同一帧只允许一个。

**音频与录制**：可以加载一段本地音频，时间轴时长会跟着音频走，播放时音画同步。录制会把画面渲染成视频文件下载，背景图、模型、音频一起合成。

**录制背景**：默认是绿幕纯色（`#00b140`），方便后期抠像。底部「背景」一栏里：

- 取色器可以改成任意颜色，画布会立即跟着变
- 「上传图片」选一张本地图片，会按画布大小拉伸铺满（画布与录制画面都按 100% 拉伸）
- 有图片时图片优先：「清除图片」去掉图片、保留当前颜色；「重置背景」则同时清掉图片并恢复默认绿幕

画布上看到的就是录制出来的背景，不用等导出。

背景设置会自动保存，和关键帧一样刷新不丢：颜色与图片都存在浏览器本地，图片本体放 IndexedDB（localStorage 只有几 MB，一张背景图就可能塞不下），启动时读回来重新生成可用的 `blob:` 地址。

图片不会被上传到任何服务器，也不会写进「导出工程」的 JSON——那里面只有关键帧、事件、时长和 FPS，换台机器需要在另一台机器上重新选择背景图。

**人物缩放**：底部「背景」右侧的「人物」一栏用来放大缩小模型，只作用于人物，背景不会跟着放大。预设 50% / 100% / 125% / 150% / 200% / 300%，也可以拖滑块或直接在输入框里填值，范围 10%–500%。缩放会一起写进录制画面，并随查看器状态保存，刷新不丢。

**工程导入导出**：时间轴上的关键帧和事件可以导出成 JSON，换台电脑或者发给别人再导入回来。

**自动保存**：当前模型、动作、表情、参数、关键帧、事件都会存进浏览器本地，刷新页面自动恢复。

## 模型资源怎么放

模型按 `public/models/<角色>/<模型名>/` 组织，例如 `public/models/tomori/live_default/`。构建和开发时插件会扫描这个目录，按下面的顺序寻找入口文件：

1. `<模型名>.model.json`
2. `model.json`
3. `<模型名>.model3.json`
4. 目录下任意 `.model3.json`

找到入口后还会检查它引用的 `.moc3`（或 `model.json` 里的 `Moc` 字段）是否真实存在。资源缺失或不完整的模型会被跳过，并在构建输出里打印一行提示，避免出现在列表里点开却是空白。

开发模式下新增或删除模型配置文件会触发页面自动刷新。

## 录制说明

录制按钮旁边可以选择导出比例：

- **跟随画布**（默认）：导出比例和当前画布完全一致，所见即所得，最长边不超过 1920。适合留档。
- **竖屏 9:16**：固定输出 1080×1920，画面按中心裁切后填满。适合发竖屏短视频，代价是画布左右或上下会被裁掉一部分。

两种模式都会把背景图和模型合成到一起，音频轨同步写进视频。编码优先 VP9，不支持时退回 VP8，输出为 `.webm`。

## 已知限制

- 录制输出是 WebM，Safari 对 MediaRecorder 的支持有限，录制按钮在检测不到能力时不会显示。
- 导出的是工程数据（关键帧、事件、时长、FPS），不含音频文件本身，导入后需要重新选择音频。
- 动作事件的时间区间依赖模型动作时长，没播放过的动作按 2 秒估算，第一次播放后才会用真实时长。
- 布局按桌面横屏设计，窄屏下侧栏和底部参数区会拥挤，暂未针对移动端适配。
